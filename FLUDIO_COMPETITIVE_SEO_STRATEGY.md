## 4. Technical Architecture: Solving the SPA Crawlability Gap

### The Current Problem
Fludio's website is currently compiled as a **React Single Page Application (SPA)** with an empty body:
```html
<body>
  <div id="root"></div>
</body>
```
* When Googlebot or search bots visit, they have to render the JavaScript bundle (`index-CuwLdb-4.js`) to see products.
* Even though Google renders JS, rendering queues introduce indexing lag (days to weeks), and AI search bots (Perplexity, Bing Copilot, ChatGPT Search) often crawl the raw HTML **without executing JavaScript**.
* In contrast, Symphony and Lumiartecnia are WordPress sites that serve full HTML on the initial HTTP response.

### The Solution (Without Changing Any Branding or Design)
We will introduce **Pre-Rendered HTML Static Generation**:
1. For every product route (e.g., `/water-fountain-products/ip68-underwater-led-spotlight/index.html`):
   * Generate an exact standalone HTML file with the same styling (`index-CCiPlLJO.css`) and scripts (`index-CuwLdb-4.js`).
   * The `<head>` will contain unique, keyword-rich `<title>`, `<meta description>`, OpenGraph, and JSON-LD schemas.
   * Inside `<div id="root">`, inject the **full semantic HTML structure** (H1, H2, specification tables, technical FAQ, product description).
2. When a user visits in the browser, React mounts seamlessly on top (hydration), preserving 100% of the interactive UI, styling, and branding.
3. When Googlebot or an AI engine visits, it reads the rich HTML and technical tables immediately, resulting in higher crawl frequency, instant indexing, and higher rankings.
